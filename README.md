# Task Manager

Task Manager — вебзастосунок для особистого списку завдань. Після реєстрації користувач може вести власні завдання, стежити за термінами й переглядати статистику.

## Можливості

- реєстрація та вхід за ім'ям користувача і паролем;
- створення, редагування, видалення та позначення завдань виконаними;
- назва, опис, категорія, пріоритет і термін виконання;
- пошук за назвою, фільтр за станом і сортування за датою, терміном, пріоритетом або назвою;
- статистика загальної кількості, виконаних, невиконаних, прострочених і високопріоритетних завдань;
- експорт списку завдань у CSV і JSON;
- окремий список завдань для кожного облікового запису.

## Технології

- **Frontend:** React 19, JavaScript, Vite;
- **Backend:** ASP.NET Core Web API, .NET 10;
- **Зберігання даних:** SQLite та Entity Framework Core;
- **Автентифікація:** JWT Bearer tokens.

## Запуск

Запустіть backend і frontend у двох окремих вікнах PowerShell з кореневої папки проєкту.

Backend:

```powershell
cd backend
dotnet run
```

API слухає `http://localhost:5000`.

Frontend:

```powershell
cd frontend
npm install
npm run dev
```

Відкрийте адресу, яку Vite покаже в терміналі; за замовчуванням це `http://localhost:5173`.

У Windows також можна запустити `start.bat`. Скрипт відкриває окремі вікна для API та клієнта і розрахований на шлях `C:\TaskManager3`. Якщо проєкт розташовано в іншій папці, запустіть команди вручну або відповідно змініть шлях у скрипті.

Під час запуску backend застосовує наявні міграції автоматично. База SQLite створюється у файлі `backend/tasks.db`.

## Налаштування

Frontend звертається до API за адресою `http://localhost:5000/api`. Backend налаштований дозволяти запити з frontend у режимі розробки.

Секрет підпису JWT задається параметром `Jwt:SecretKey` у конфігурації ASP.NET Core. Для локальної розробки його можна передати через змінну середовища PowerShell:

```powershell
$env:Jwt__SecretKey = "ваш-власний-довгий-випадковий-секрет"
cd backend
dotnet run
```

Змінна середовища має вищий пріоритет за значення у `appsettings.json`. Для розгортання використовуйте власний секрет через безпечне сховище конфігурації; не публікуйте реальні секрети або локальну базу даних у репозиторії.

## API

Усі адреси нижче наведені відносно `http://localhost:5000`. Для захищених маршрутів передавайте заголовок `Authorization: Bearer <token>`.

| Метод | Маршрут | Доступ | Призначення |
|---|---|---|---|
| `POST` | `/api/auth/register` | Публічний | Створити обліковий запис |
| `POST` | `/api/auth/login` | Публічний | Увійти й отримати JWT |
| `GET` | `/api/tasks` | JWT | Отримати завдання поточного користувача |
| `POST` | `/api/tasks` | JWT | Створити завдання |
| `PUT` | `/api/tasks/{id}` | JWT | Оновити завдання |
| `DELETE` | `/api/tasks/{id}` | JWT | Видалити завдання |
| `GET` | `/api/statistics` | JWT | Отримати статистику завдань |
| `GET` | `/api/statistics/categories` | JWT | Отримати категорії користувача |

Реєстрація приймає JSON з полями `username` і `password`. Ім'я має містити щонайменше 3 символи, пароль — щонайменше 6. Вхід приймає ті самі поля та повертає об'єкт із `token`.

Завдання містить поля `title`, `description`, `isCompleted`, `priority`, `category` і `dueDate`. Назва обов'язкова; стандартний пріоритет — `Medium`, категорія — `General`. Дати передавайте у форматі ISO 8601.

Зараз `PUT /api/tasks/{id}` зберігає назву, опис, статус виконання та пріоритет. Категорію й термін виконання цей маршрут поки не оновлює.

## Примітки

- Токен входу зберігається у `localStorage` браузера й використовується для запитів до захищених маршрутів.
- Експорт CSV і JSON виконується у браузері на основі завантаженого списку завдань.
- Файл `frontend/DEVELOPMENT_PLAN.md` містить план розробки інтерфейсу.
